# Build Log — 2026-10-23

## Round 1 of 3

Verification method this round: `pnpm typecheck` (tsc --noEmit, 0 errors) and `npx eslint` on
every touched file (0 errors; only pre-existing unrelated warnings) after each feature, run
from `apps/web`. A real Postgres/Redis dev environment was not already configured for this
repo (`.env` only has `.env.example`/`.env.selfhost.example`), and standing up one would have
required `prisma migrate`/`db push`, which is explicitly off-limits unless asked — so this
round deliberately avoided any schema change and relied on strict type-checking plus manual
read-through of every new query against the real Prisma schema instead of a live dev server.

   - New `apps/web/src/server/api/routers/topic.ts`: team CRUD (`list`/`create`/`update`/

     `getPublicPreferences` / `updatePublicPreferences` — that reuse the exact signed
     `id`+`hash` scheme already used by unsubscribe links (`verifyUnsubscribeLink`, now
     exported from `campaign-service.ts` instead of duplicated).
   - New `TopicService.getPublicPreferencesFromLink` / `updatePublicPreferencesFromLink` in
     `topic-service.ts`: resolve the contact's team from the link, return/update only
     `PUBLIC`-visibility topics, silently rejecting any topicId outside that team.
   - Admin CRUD UI: `apps/web/src/app/(dashboard)/contacts/topics/` (list, create/edit dialog,
     type-to-confirm delete via the shared `DeleteResource` component). Linked from the
     Contact books page header.
   - Public preference center: `apps/web/src/app/unsubscribe/topic-preferences.tsx`, rendered
     on `/unsubscribe` below the existing unsubscribe card whenever the link is valid and the
     team has at least one public topic — lets a recipient flip individual topics on/off
     (e.g. stay subscribed to "Product updates" but opt out of "Promotions") without
     unsubscribing from everything.
