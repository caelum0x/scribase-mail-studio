---
title: Self hosting Scribase Mail
description: "Run Scribase Mail on your own server with Postgres, Redis and Oracle Cloud Email Delivery."
---

## Prerequisites

- A server that runs Docker (1.5 GB RAM is enough for web, Postgres and Redis)
- An [Oracle Cloud](https://www.oracle.com/cloud/) tenancy with Email Delivery enabled
- A domain you can add DNS records to

Scribase Mail sends through Oracle Cloud Infrastructure (OCI) Email Delivery: SMTP for
sending, and the Email Delivery API for domains, DKIM, approved senders and the
suppression list. Postgres stores your data and Redis runs the queues.

## Step 1: Environment variables

Copy `.env.selfhost.example` to `.env` and fill in the values.

<Steps>
  <Step title="OCI SMTP credentials (sending)">
  In the OCI console open **Identity > Users > your user > SMTP credentials** and
  generate a credential. Use the SMTP endpoint of your region.

```env
SMTP_HOST="smtp.email.eu-frankfurt-1.oci.oraclecloud.com"
SMTP_PORT="587"
SMTP_USER="<smtp-credential-username>"
SMTP_PASS="<smtp-credential-password>"
```

  </Step>
  <Step title="OCI API key (domains, DKIM, suppressions)">
  Create an API signing key for a user that may manage Email Delivery in the
  compartment (policy: `Allow group <group> to manage email-family in compartment <compartment>`).

```env
OCI_REGION="eu-frankfurt-1"
OCI_TENANCY="ocid1.tenancy.oc1..<...>"
OCI_USER="ocid1.user.oc1..<...>"
OCI_FINGERPRINT="<api-key-fingerprint>"
# PEM contents (\n escapes are fine), or mount the file and use OCI_PRIVATE_KEY_PATH
OCI_PRIVATE_KEY="-----BEGIN PRIVATE KEY-----\n...\n-----END PRIVATE KEY-----"
# Optional, defaults to the tenancy (root compartment)
OCI_COMPARTMENT_ID="ocid1.compartment.oc1..<...>"
```

  </Step>
  <Step title="Login">
  Users sign in with a one-time code sent by email. Set `FROM_EMAIL` to an
  address on a domain that is already set up in OCI Email Delivery; system
  emails (sign-in codes, invites, notifications) are sent from it directly, so
  you can sign in before adding any domain in the dashboard.

```env
FROM_EMAIL="Scribase Mail <noreply@mail.example.com>"
```

GitHub and Google login also work: set `GITHUB_ID` / `GITHUB_SECRET` or
`GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET`. The GitHub callback URL is
`https://<your-instance>/api/auth/callback/github`.

  </Step>
  <Step title="Database & Redis">

```env
DATABASE_URL="postgres://<username>:<password>@<host>:<port>/<database-name>"
REDIS_URL="redis://<host>:<port>"
```

If you share Redis between apps, set `REDIS_KEY_PREFIX` to namespace all keys.

  </Step>
  <Step title="App URL and secret">

```sh
openssl rand -base64 32
```

```env
NEXTAUTH_URL="https://mail.example.com"
NEXTAUTH_SECRET="<random-secret>"
```

`NEXTAUTH_URL` is also the base for open/click tracking links and unsubscribe
links, so it must be reachable from the internet. `NEXTAUTH_SECRET` signs the
tracking links.

  </Step>
  <Step title="Optional settings">

```env
# Poll interval for bounces and complaints (cron, UTC). Default every 5 minutes.
SUPPRESSION_POLL_CRON="*/5 * * * *"
# Poll interval for delivered/bounced/complained events from the OCI Email
# Delivery logs (cron, UTC). Default every minute.
DELIVERY_LOG_POLL_CRON="* * * * *"
# OCI Logging log group created for the Email Delivery service logs
OCI_LOG_GROUP_NAME="scribase-mail"
# Clear stored email bodies after N days
EMAIL_CLEANUP_DAYS=30
# Image uploads in the editor (OCI Object Storage)
OCI_STORAGE_NAMESPACE="<namespace>"
OCI_STORAGE_BUCKET="scribase-mail-images"
STORAGE_PUBLIC_URL="https://objectstorage.eu-frankfurt-1.oraclecloud.com/n/<namespace>/b/scribase-mail-images/o"
```

  </Step>
</Steps>

## Step 2: Run the app

Use the compose file in `deploy/compose.scribase-mail.yml` (web, Postgres and
Redis with memory limits). See `deploy/DEPLOY.md` in the repository.

## Step 3: Check the provider

Sign in as the admin (`ADMIN_EMAIL`) and open **Admin > Email provider**. It
shows whether the SMTP relay and the Email Delivery API are reachable and lets
you set the send rate. No other setup is needed.

## Step 4: Add a domain

Add your domain in **Domains**. Scribase Mail creates the email domain and a
DKIM key in OCI and shows the records to publish:

| Type  | Name                       | Value                                              |
| ----- | -------------------------- | -------------------------------------------------- |
| CNAME | `<selector>._domainkey`    | `<selector>.<domain>.dkim.<region>.oracleemaildelivery.com` |
| TXT   | `@` (or your subdomain)    | `v=spf1 include:rp.oracleemaildelivery.com ~all`   |
| TXT   | `_dmarc` (recommended)     | `v=DMARC1; p=none;`                                |

Verification runs automatically. Every From address must be an approved sender
in OCI: Scribase Mail creates it on the first send from a new address, or you
can add senders on the domain page ahead of time.

See [OCI Email Delivery notes](/self-hosting/oci-email-delivery) for what is
different from push-based providers.

## Step 5: SMTP proxy (optional)

`apps/smtp-server` accepts SMTP from apps that cannot call the REST API and
forwards each message to the Scribase Mail API. The SMTP password is a Scribase
Mail API key.

```yaml
services:
  smtp-server:
    build:
      context: apps/smtp-server
    environment:
      SMTP_AUTH_USERNAME: "scribase"
      USESEND_BASE_URL: "https://mail.example.com"
    ports:
      - "587:587"
      - "465:465"
    restart: unless-stopped
```

Show the host and username to your users with `SMTP_PUBLIC_HOST` and
`SMTP_PUBLIC_USER` in the web app environment.
